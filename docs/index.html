이 값은 문서가 전제로 삼는 관리 기준이다. 저장소가 현재 머신을 자동으로 검사하거나 변경한다는 뜻은 아니다.

적용 기준을 바꿀 때는 각 원칙 문서의 기본 환경 표와 재설치 절차에서 같은 전제를 사용하는 부분을 함께 검토한다.

문서

소프트웨어 설치 원칙도구 종류에 따른 설치 방식과 설치 전후 판단 기준디렉토리 관리 원칙$HOME, 프로젝트, 문서, 임시 파일과 애플리케이션 생성 경로의 관리 기준개발환경 구성 원칙Homebrew, runtime, dependency, 개발 도구의 구성 기준Shell 설정 원칙.zprofile, .zshrc, alias와 PATH의 책임 분리Git과 GitHub SSH 설정 원칙Git 사용자 정보와 GitHub SSH 연결의 설정·검증 기준재설치 원칙초기화 또는 새 Mac에서 원칙을 다시 적용하는 순서

처음 구성하거나 새 Mac에서 시작할 때는 재설치 원칙부터 읽는다. 이 문서가 나머지 다섯 문서를 순서대로 호출한다. 개별 기준만 확인할 때는 해당 문서를 직접 읽는다.

문서 관리 원칙

  • 하나의 사실에 관한 기준은 한 문서에서만 관리한다. 다른 문서에서는 기준을 소유한 문서로 링크한다.
  • 상세한 문서 표기·용어·구조 규칙은 AGENTS.md에서 관리한다.
  • 설정이나 선택을 기록할 때는 이유, 적용 위치, 검증 방법, 제거 방법을 함께 설명한다.
  • macOS나 도구의 version에 따라 바뀔 수 있는 명령은 공식 문서를 다시 확인하도록 명시한다.
  • 기존 문서와 다른 책임이 생길 때만 새 파일을 추가한다.

변경 흐름

  1. 기존 원칙과 충돌하거나 중복되는지 확인한다.
  2. 선택의 이유와 대안을 정리한다.
  3. 책임이 가장 가까운 문서 한 곳을 수정한다.
  4. 관련 문서의 링크와 표현을 함께 검토한다.
  5. secret 또는 머신 고유 정보가 포함되지 않았는지 확인한다.

현재 범위 밖의 항목

이 문서가 다루지 않는 것 펼치기
  • 현재 머신의 설치 애플리케이션 및 CLI 목록이 저장소는 원칙만 관리하고 머신의 현재 상태는 관리하지 않는다.
  • 실제 dotfiles 원본과 머신별 override문서는 배치와 책임만 설명하고 실제 설정 파일은 관리하지 않는다.
  • password, token, SSH key, 인증서 private key개인 계정 정보와 secret은 관리 대상이 아니다.
  • package 설치·삭제 또는 시스템 설정을 실행하는 자동화저장소가 현재 머신을 자동으로 변경하지 않는다.
  • 자동으로 $HOME에 설정 파일을 배포하는 bootstrap 기능먼저 수동 절차와 안전 조건을 문서화하고 반복 필요가 확인될 때 별도 책임으로 검토한다.

설정 예시나 script를 반복해서 사용할 필요가 생길 때만 별도 디렉토리를 추가한다. 먼저 수동 절차와 안전 조건을 문서화한다.
