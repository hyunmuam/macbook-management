AGENTS.md

저장소 책임

  • 이 저장소는 개인 macOS 운영 원칙을 한국어 문서로 관리한다.
  • 관리 대상은 이 파일, README, 여섯 원칙 문서, LICENSE, 렌더 script(tools/)와 생성물(docs/)이다.
  • 문서의 정본은 저장소 최상위의 마크다운 파일이다. docs/는 정본이 아니다.
  • 저장소의 범위 밖 항목은 README 「현재 범위 밖의 항목」에서 관리한다.
  • _workspace/는 로컬 전용 작업 기록이므로 읽거나 수정하거나 검색 대상에 포함하지 않는다.

문서 구조

  • reinstallation.md를 제외한 다섯 원칙 문서는 문서 목적, 기본 환경, 전체 구성, 구성 원칙, 설정 방법, 검증, 이후 사용 및 유지보수, 현재 범위 밖의 항목, 핵심 요약을 아홉 개 척추 절로 두고 같은 상대 순서로 유지한다.
  • 문서 고유의 절은 척추 절 사이에 추가할 수 있다. 척추 절의 이름을 변경·병합·생략하지 않는다.
  • reinstallation.md는 나머지 원칙 문서를 순서대로 호출하는 orchestrator 절차를 담기 때문에 별도의 절 구성을 따른다.
  • 구조상 허용되는 변경이라도 명시적인 요청 없이 절을 추가·삭제·이동하거나 문서를 분할·병합하지 않는다.
  • docs/ 아래 파일은 tools/render.py가 생성한다. 직접 수정하지 않는다. 내용을 바꿀 때는 마크다운 원본을 고치고 script를 다시 실행한다.
  • 척추 절의 이름은 렌더링 규칙의 입력이다. 이름을 바꾸면 해당 절이 일반 절로 렌더링되므로 구조 규칙과 함께 확인한다.
  • 다섯 원칙 문서의 핵심 요약에 있는 원칙 링크는 해당 문서의 구성 원칙 제목과 1:1로 유지한다.

표기 및 용어

구분규칙예
영문 일반명사본문에서는 소문자로 표기한다.architecture, service, local
제목·항목 표기문서 제목(H1), 문서명, 링크 텍스트의 문서명, 문장 첫 단어와 불릿·표 셀의 항목명은 소문자화 대상에서 제외한다. 이 예외가 대문자를 강제하지는 않는다.Shell 설정 원칙
명령 유래 용어문장 위치와 관계없이 원래 명령과 같은 표기를 유지한다.git clone의 clone
명령 출력 필드·UI 레이블원문을 그대로 인용할 때는 원문 표기를 유지한다.Client / Server, Warp Prompt / Input Editor, GitHub Pull Request / Issue, macOS System Settings / Options
고유명사·기술 식별자제품명, 약어, 경로명, 설정 키와 code identifier의 공식 표기를 유지한다.Homebrew, GitHub, CLI, IdentityFile
  • 실제 사용자명, 이메일, 기기 이름과 절대 경로 대신 <github-email>, <project-root>처럼 의미가 드러나는 대체 표기를 사용한다.

변경 원칙

  • 원칙의 내용, 판단 기준과 결론을 바꾸지 않고 표기·구조·문장 형태만 요청 범위에서 수정한다.
  • 제목 변경으로 앵커가 바뀌면 해당 앵커를 가리키는 링크를 전수 확인한다.
  • 기준 version 값은 개발환경 구성 원칙이 소유한다. 요청 없이 바꾸지 않는다.
  • 통합 version manager에 관한 서술을 추가하지 않는다.
  • 검증할 수 없는 명령을 쓰거나 기존 문서에 새로운 명령·검증 절차를 만들지 않는다.
  • 변경 이력은 Git 이력으로 관리하고 문서 안에 changelog를 만들지 않는다.
  • 마크다운 문서를 수정한 뒤에는 python3 tools/render.py를 실행하고 생성물을 같은 commit에 포함한다.

검증

  • 모든 상대 링크와 앵커가 유효한지 확인한다.
  • 다섯 원칙 문서의 척추 절 이름과 상대 순서가 같은지 확인한다.
  • 다섯 원칙 문서의 핵심 요약 원칙 링크가 구성 원칙 제목과 1:1로 일치하는지 확인한다.
  • 표기 변경 뒤에는 대상 문자열의 잔존 여부와 의도적으로 유지한 예외를 함께 확인한다.
  • 이 파일의 관리 대상·문서 구조·표기 및 용어 규칙이 README와 여섯 원칙 문서의 실제 상태와 일치하는지 대조한다.
  • 렌더링 후 docs/의 변경 범위가 마크다운 변경 범위와 일치하는지 확인한다.
  • 생성된 HTML의 내부 앵커와 문서 간 링크가 모두 유효한지 확인한다.
  • 생성된 HTML의 목차 항목 수가 마크다운 문서의 헤딩 수와 일치하는지 확인한다.
이 페이지는 AGENTS.md에서 생성되었다. 직접 수정하지 않는다.
